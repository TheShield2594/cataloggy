# Changelog

All notable changes to Cataloggy are documented in this file, starting from this entry onward. Earlier history predates this file — see `git log` for the full commit history.

Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Dates are UTC.

## [Unreleased]

### Added

- Play detection for any app that supports Stremio add-ons. The add-on protocol is read-only — a client asks an add-on for things and can never report what it watched — so apps that keep their library to themselves (Vidi, Omni, Nuvio and similar) had no way to reach Cataloggy except the manual "Cataloggy: Mark Watched" subtitle entry. The asking itself carries intent, though: a `stream` request means a title's stream list was opened, and a `subtitles` request means a player loaded. The add-on now declares the `stream` resource purely to receive that request — always answering with an empty list, so nothing extra appears in the client — and forwards both signals. A signal opens a pending play due at 80% of the title's runtime (the threshold a real scrobble uses), promoted to a watch when that elapses or immediately when the next episode of the same series starts, and discarded if a different title is opened within two minutes. Nothing pending is treated as history, and it lives in its own table rather than `ScrobbleSession` so `/scrobble/now-playing` never reports a guess as live playback. Off by default (`STREMIO_PLAY_DETECTION`, needed on both the `api` and `addon` services) because it infers completion rather than observing it, with a **Settings → Play Detection** panel listing what is pending, which resource produced it and which client sent it.

- Stremio watched sync: Cataloggy can now read watched state straight from a connected Stremio account, so anything finished in Stremio is marked watched here without Trakt relaying it. Stremio's add-on protocol is read-only — an add-on is never told what you watched, which is why marking watched from Stremio previously meant picking a fake "Cataloggy: Mark Watched" subtitle by hand — but every client signed in to a Stremio account syncs its library to Stremio's servers, and one connection covers all of them (desktop, mobile, Android TV, web, and third-party clients using a Stremio account) with nothing to install per device. Connect under **Settings → Stremio Watched Sync**; the password is exchanged for an access key once and never stored. Connecting only starts tracking from that moment, with a separate one-time import for history the account already has, dated from Stremio's own watch history. Both automatic mechanisms ship off, so one has to be enabled for anything to sync on its own: either the scheduled poll (`STREMIO_POLL_INTERVAL_SEC`, for Stremio's own exact watched state) or play detection (for an inference that also covers non-Stremio clients) — otherwise syncing is the **Sync now** button. The poll costs a single small request when nothing has been watched, and failures surface in the existing Sync Status section.

- iOS launch screens for the installed PWA (`apple-touch-startup-image`), covering iPhone SE through iPhone 17 Pro Max and the current iPads in both orientations, so launching from the home screen shows the branded splash instead of a blank white flash. Generated by `scripts/generate-splash.mjs`; excluded from the service-worker precache so they cost nothing at install time.
- Docker images are now also published with a `sha-<short-sha>` tag (and a semver tag for `vX.Y.Z` tag pushes), so self-hosters can pin a known-good version and roll back instead of only ever running `:latest`.
- pnpm is now pinned to 11 (from 9.12.0). pnpm 11 stopped reading settings from `package.json` and `.npmrc`, so the dependency `overrides` (several of them CVE pins) and the hoisted node-linker moved to `pnpm-workspace.yaml`, joined by an `allowBuilds` list — pnpm no longer runs a dependency's install scripts unless it's approved, and Prisma and esbuild both need theirs. No resolved dependency version changed: `pnpm-lock.yaml` is untouched by the migration.
- CI, the Docker publish pipeline and the weekly security scan now run on Node 26, matching the `node:26-alpine` base image every app ships on, instead of the end-of-life Node 20 they were pinned to.
- CI now applies every Prisma migration against a real Postgres service before running tests, catching broken migrations before they reach a self-hoster's `api` container.
- CI now runs CodeQL static analysis and a `pnpm audit` dependency check (weekly, plus every push/PR).
- README: guidance on pinning/rolling back image versions, and on recovering if a database migration fails on container start.
- `CONTRIBUTING.md`.
- A "Sync Status" Settings section and `GET /settings/job-status` endpoint surfacing the last failure of each scheduled background job (Trakt poll/watchlist sync, episode notifications, AI recs refresh, Steam sync, scrobble cleanup), so a self-hoster without Sentry configured can still notice a silently-broken sync.
- A visible "update available" prompt for the web PWA instead of the service worker silently swapping itself in.
- `PATCH /profiles/:id` for renaming a profile or setting/changing/removing its PIN, plus a Settings UI to do so — previously only creating and switching profiles was possible from the app; deleting one (already supported server-side) had no UI entry point at all.
- `apps/web` now has a test suite (Vitest + Testing Library + jsdom, run by `pnpm test` like the other workspaces) — previously the ~11k-line frontend was covered only by ESLint and the type checker, with nothing exercising its behavior. Covers the pure logic (`timeAgo`/`timeUntil`, carousel edge fade and scroll state, runtime/status formatting, Continue Watching progress), the `useSearchFilters` URL-param reducer, the `api.ts` request wrapper (auth headers, both 401 paths, error decoding), and the profile switcher / PIN entry flow.
- A "Skip to main content" link as the first focusable element in the shell, so a keyboard or screen-reader user no longer traverses the sidebar and top bar on every route. It targets `<main>`, which gains an `id` and `tabIndex={-1}`; SPA navigation now moves focus into `<main>` too, instead of leaving it on the nav item that was clicked with the new page's announcement lost. The two `<nav>` landmarks are distinguishable — "Primary" for the sidebar and "Mobile navigation" for the bottom tab bar, previously both unlabelled and "Main" respectively — and the Lists page's inner `<main>` is a `<div>`, since the shell already owns that landmark.
- Test coverage for previously-untested modules: `lib/collection.ts`, `lib/watchlist.ts`, `lib/series-progress.ts`, `routes/watch.ts`, the Plex/Jellyfin webhook handlers, and the new profile-management/job-status endpoints. `apps/addon` now has a test suite of its own (previously it had none), covering profile scoping and mark-watched feedback.

### Changed

- The Glass theme frosts the screen now, not just the header. It is described as frosted glass over a deep ambient backdrop, and the CSS had the backdrop, the blur token and the rule to apply it — but the rule reached `.glass-surface`, a class worn by exactly one element in the app, and `header`. Everything else stayed flat dark navy with almost nothing translucent for the ambient gradients to show through, so the theme mostly read as a bluer dark mode. The surfaces that make up the bulk of a screen opt in now: the sidebar, both detail panels, the dialogs and the mobile sheet take the full blur as `.glass-surface`; the settings sections, stat tiles, stats and dashboard cards, and the calendar, history and list rows take a lighter one as `.glass-panel`. The split is about cost — a dashboard can stack a dozen in-flow panels, and each blurred layer is a full-surface composite, while there are never more than one or two floating surfaces on screen. Below 640px the panels drop the blur for a denser flat tint, since phones and TV browsers are where the frames actually cost something and where the least backdrop shows around a panel anyway, and `prefers-reduced-transparency: reduce` turns the whole effect off. Hoverable rows carry `.glass-row` rather than `.glass-panel`: the tint has to be `!important` to beat the inline background nearly every surface sets from a token, which also beat the `hover:` utility those rows answered the pointer with, so the hover state is restated as a tint of its own.

- The search page shows one search field again. Arriving at `/search` put two on screen: the page's own full-width field, and the header's — which is not a field at all but a button that opens the command palette, so typing into it swapped the whole page for an overlay. Neither said which one the page was about to use. The header trigger now stands down on that one route, leaving a spacer so the theme, install and profile controls stay where they are on every other page; ⌘K still reaches the palette from anywhere, search page included. The panel underneath it also settles on two corner radii instead of four — surfaces are `rounded-2xl` (the bar, and the advanced-filter grid inside it), controls are pills (the query field, the type toggle, the year inputs, the sort and genre selects) — where a full pill sat inside a 2xl box wrapping an xl grid of lg fields, which read as four unrelated widgets stacked rather than one panel.

- The dashboard's greeting-and-stats strip is a ticket stub now: page-coloured bites out of its left and right edges, the silhouette the Stats page's `TicketTile` is named for but never actually drew. It is the one place the motif earns its keep daily — that row carries the same collectible numbers (plays this week, streak, movies, episodes) on every visit, where the tiles are on a page most people open monthly. The notches are absolutely positioned inside the strip's own padding, so they take no width: the row is a single line of chips on a 1280px laptop with the sidebar pinned, and a decoration that took even 20px wrapped the date onto a second line. The stat values also carry tabular figures now, so a count ticking up no longer shuffles the label beside it.

- The wordmark beside the mark is set as a wordmark now, rather than in the app's own heading style. At `font-bold` with default tracking, "Cataloggy" was typographically identical to a page heading like "Games" or "Calendar" — the same family, weight and spacing — so it read as one more label rather than the product's name. It moves to 800 with the tracking pulled in, which is the whole change in the sidebar and the mobile top bar. First run and the profile picker, which are nothing but brand, get a stacked lockup instead: a larger mark above the name, with the old logo art's "Track your movies & shows" line returned underneath it — the tagline gives the name a base to sit on, so a tall mark over one short word stops reading as two things that happen to be near each other. The wizard's first step is headed "Connect your server" rather than "Welcome to Cataloggy", which put the product's name twice within an inch of itself now that the lockup above it says so louder — a step's heading is better spent saying what the step wants.

- The Stremio add-on now offers Cataloggy's icon as its logo (both the `api` and `addon` manifests), so it appears with its own tile in Stremio's add-on list instead of the generic placeholder. Stremio fetches the image itself, so this needs `CATALOGGY_WEB_PUBLIC` set — without it the manifests behave exactly as before. `CATALOGGY_WEB_PUBLIC` now has its trailing slash trimmed in the `addon` service too, matching `api`; a value ending in `/` previously produced a `//settings` configure link.

- New logo: a cat curled into a C around a play button, flat and single-weight, replacing the 3D-glasses mascot everywhere it appeared — the app's brand lockups (sidebar, mobile top bar, setup wizard, profile switcher), the browser tab, the installed app's icon and the iOS launch screens. It is drawn as vector now rather than resized from a 1.2 MB render, which is what makes the rest of this possible: `apps/web/public/logo.svg` is ~4 kB and serves the tab directly (with its ink following the browser's light/dark UI, since the old icon was near-black on every Chrome dark tab strip), the PWA icons rebuild from it at 3.5 kB and 7 kB rather than 10 kB and 43 kB, and the 46 launch screens total 1.1 MB instead of 2.4 MB. In the app the mark is inlined by a `BrandMark` component so the cat takes the current theme's text colour — the previous mascot sat in a filled accent tile precisely because it could not — while the play disc keeps its amber in every theme. The four lockups no longer use the `Clapperboard` icon, which stays what it always was elsewhere: the Dashboard's nav icon. `scripts/generate-icons.mjs` regenerates the icons and the favicon, `scripts/generate-splash.mjs` the launch screens; both read the same SVG, and both need re-running if it changes.

- Loading got noticeably shorter, in four places. **Install and first paint:** `apps/web/public/icons/` held two byte-identical copies of the 1.2 MB source logo, referenced by nothing but the splash-screen generator — and because everything under `public/` is copied into `dist/` and matched by the service worker's `**/*.png` precache glob, every install downloaded both. The generator's copy moved to `apps/web/brand/` (outside the build) and the duplicate is gone, taking the precache from 3.4 MB to 1.4 MB. **Entry bundle:** `@sentry/react` was imported statically by the app's entry module, so all ~28 kB gzipped of it loaded on every visit, including the majority of self-hosted installs that never set a DSN. It now lives in its own chunk, fetched on idle only when a DSN is configured; first-load JS + CSS drops from 138 kB to 113 kB gzipped. Errors raised before the chunk lands are held on its load promise rather than dropped. **Opening a page:** every route but the dashboard is code-split, so the first visit to one spent a round trip fetching its chunk before the page could even begin requesting data — that round trip was most of what the spinner after a nav click actually was. Sidebar links now start their route's chunk on hover or keyboard focus, mobile tabs start theirs on touch-down, and the chunks a tap can reach with no hover to warn us first (search, lists, calendar, history, and the detail panel) are warmed on idle once the dashboard has finished its own work — skipped entirely when the browser reports a metered or 2G connection. Settings is left out of the idle pass deliberately: largest chunk, least-visited page. **Posters:** the browser opens its connection to `image.tmdb.org` alongside the app's own JS now instead of when the first `<img>` resolves, the API host gets the same treatment at startup when it is a separate origin, and poster art from TMDB, IGDB, Steam and RatingPosterDB is cached by the service worker — so a poster is fetched once rather than on every session the HTTP cache has since evicted, and a library you have already browsed keeps its artwork offline instead of falling back to initials on a gradient.

- A second pass on loading, going after the waits the first one left behind. **Data survives leaving a page.** Every page refetched from scratch on mount, so returning to one you left ten seconds ago showed a spinner over an answer the tab already had — the service worker made the response fast, but the component couldn't know that and rendered the spinner regardless. There is now a cache the render pass reads synchronously, scoped to the profile and token that fetched the data and cleared on any mutation, so the dashboard, history, calendar, stats, lists and games pages paint their last known content in the first frame and refresh underneath it. Games keys on sort order, so flipping back to an order already seen is instant too. **One request per detail panel, not six.** Opening a title fired meta, cast, providers, recommendations and — for a series — seasons and dropped-state in parallel, each resolving the same TMDB ID separately, the panel filling in only as the slowest landed; a single bundle endpoint now does the resolution once and returns it together, and reopening a title within a minute costs nothing. **The API answers less.** Responses were uncompressed and carried no validator, so a full watchlist crossed the wire in full every time and an unchanged one crossed it again — now compressed, and split on whether the user can change the answer: TMDB facts get a real `max-age`, user-owned data gets an ETag and a bodyless 304. Nothing is `public` and `Vary` carries the identity, since these responses are private to one profile. In-flight upstream lookups are shared, so a burst of requests for one title makes one call rather than six. **Requests start before the bundle does.** The dashboard's opening queries could not begin until the entry chunk had downloaded, parsed, and mounted React; a small script in the page head now starts them during HTML parse and the app adopts the in-flight responses. **Navigation warms data, not just code.** Hovering a nav link already fetched the route's chunk; it now fetches what that page opens with as well, skipped when the data is still fresh or the connection is metered. **Smaller on the wire.** The two PWA icons are re-encoded (197 KB to 52 KB, same artwork), the command palette leaves the entry bundle until first opened, the latin font subset is preloaded, and the poster srcset gained w92/w154 steps so the small tiles stop downloading four times the bytes they display — with `fetchpriority` sorting above-fold artwork ahead of the rest, and the three pages that hand-roll their own `<img>` finally getting a srcset at all.

- The installed PWA no longer behaves like a scrollable document. A phone browser hands any page pinch-to-zoom, double-tap-to-zoom, rubber-band overscroll and a zoom-in on every focused field whose text sits under 16px. That is fine in a tab, where the address bar says "web page" and zooming back out is a known gesture — but the installed app has no chrome at all, so a stray two-finger drag left it zoomed and off-centre with nothing on screen explaining how to get back, and a swipe past the end of a list dragged the fixed header and tab bar off position with it. Running installed now pins the viewport (`user-scalable=no` plus `touch-action: pan-x pan-y`, and the WebKit `gesture*` events iOS routes around the meta tag), stops overscroll — that rubber-band, and Chrome's pull-to-refresh, which in an app with no reload button just blanks the screen — and drops the long-press callout and image-drag preview on posters and controls, both of which fire on a mis-timed tap. Vertical scrolling and the carousels' horizontal panning are untouched. A browser tab keeps every one of those gestures, since removing pinch-zoom there would fail WCAG 1.4.4; `data-display-mode` on `<html>`, set before the first paint and re-checked when Chrome moves a live tab into an installed window, is what separates the two. Two of the fixes apply to any touch device rather than only to the installed app: form fields hold a 16px floor, so focusing one no longer zooms the page in and leaves it there, and controls opt out of the double-tap-zoom wait. The search page's year range was retuned to fit four digits at the larger size.

- Trakt no longer removes anything from your library. The watchlist sync mirrored Trakt-side removals by deleting the local item, which made Trakt authoritative over a self-hosted library — and meant a Trakt that answered `200` with an empty watchlist (a reset account, a token rebound elsewhere, an API that stops carrying data rather than erroring) would empty the local watchlist along with it. HTTP failures were always safe, since the client throws on any non-2xx and the sync aborts before touching anything; a healthy-looking empty body was not. Mirroring removals is now opt-in via `TRAKT_WATCHLIST_MIRROR_DELETES=true`, and even with it on, a watchlist that has gone entirely empty is treated as a fault and skipped. Kept items are recorded in the sync snapshot rather than left out of it, so the next run doesn't read them as a local add that never reached Trakt and push them back up — a removal on Trakt stays a removal there without resurrecting, and without taking the local copy with it.

- Toasts are readable and interruptible. An error carried the only copy of a failure reason — `Created "X", but couldn't add "Y" (reason)` — on the same flat 3-second timer as a "Saved" confirmation, which isn't long enough to read one; errors now hold for 10 seconds. Hovering the stack, or tabbing into it, stops the clock on every toast in it and resumes with the time that was left, so reaching for Undo or the close button is no longer a race against a timer that could pull the button out from under the click. And dismissing a toast now plays the `.toast-exit` animation that has been defined in `index.css` all along and never once applied — toasts were unmounted directly by the state update, so they vanished mid-stack; the unmount now waits for the animation to end, with a timer backing it up for the cases where that event never arrives.
- Empty states point somewhere. "No series in progress", "No watch history yet" (on both the dashboard and the History page) and the calendar's empty agenda described the situation and offered no way out of it — and these are the states a brand-new install shows on every screen, so they were the first thing a user saw after setup. Each now says what fills it and links to search, following the pattern the TMDB-key states already used. The calendar's also says what it covers — only series already in progress — which is what made an empty one impossible to tell apart from a broken one.
- The Lists page keeps its selection in the URL (`/lists?list=<id>`) instead of in component state, so a list can be linked and bookmarked, Back undoes a list switch, and a reload returns to the list you were on rather than the first one. The route was declared `/lists/*`, promising sub-routes it never had — `/lists/anything` silently rendered the same page — and is now a plain `/lists`, so a stale sub-path 404s honestly. Landing without a list named still picks the first one, replacing that history entry rather than pushing it so Back leaves the page as before; a link to a list that has since been deleted says so instead of showing an empty selection.
- The calendar's month view is no longer offered below `sm:`, where seven columns leave each day about 50px wide holding truncated titles at `text-2xs`. Phones get the agenda view, which was always the readable one, and the view toggle is dropped rather than left pointing at something unusable. Two dead ends in the grid itself are gone too: `+N more` was plain text naming episodes with no way to reach them and is now a button opening the day's full list, and ◀ is disabled at the current month with an explanation, where it previously paged into blank grids — the API only ever returns upcoming episodes, so every past month rendered empty with nothing said about why. The future side already explained itself.
- The setup wizard's steps go both ways. Each of the four only moved forward, so a token that verified against the wrong server, or a Trakt connection started by mistake, could only be revisited by clearing `localStorage`; every step past the first now has a Back button, and returning to the token step prefills the token that got you there. The progress indicator was three bare bars with no text, no `aria-label` and no `role` — it now carries a visible "Step N of 4" and reports as a `progressbar` to assistive technology.
- The base layer transitions colours only, rather than `transition-all`, on `button`, `a`, `input` and `select`. `transition-all` animates layout properties too, so anything that changed size on a state change eased into it over 200ms instead of snapping, and it fought the narrower `transition-colors`/`transition-transform` declared at individual call sites; it also scheduled transitions on every hover for properties that weren't changing, across grids of 60+ cards. Components that genuinely need transform or size animation already opt in themselves. The `prefers-reduced-motion` block is unaffected.
- Destructive actions are undoable rather than confirmed four different ways. Removing an item from a list, deleting a watch event (on the History page and in the detail panel's watch history) and dropping a show now apply immediately and raise a toast carrying an **Undo**; the toast stays up for 8 seconds rather than the usual 3, and Undo re-adds the list item, re-logs the watch event or un-drops the show. The two actions with the highest traffic — remove-from-list and delete-watch-event — previously confirmed nothing at all, and both render at full opacity on touch directly on top of a card whose whole surface is a tap target, so a mis-tap destroyed data silently. Dropping a show loses its `window.confirm`, the only blocking dialog in an otherwise toast-driven flow. Deleting a *list* keeps its inline confirm card: a list can only be "restored" by creating a new one, which mints a new id and so would not restore the Stremio catalog (`list:<id>`) wired to the old one — an honest confirm beats an undo that quietly gives back something different. Deleting a profile keeps its hard confirm, being genuinely unrecoverable.
- The detail panel leads with what the title *is* rather than with somewhere to file it. The overview sat eighth, below lists, external ratings, external links, star rating, tags and the check-in block, so opening something unfamiliar meant scrolling past six tracking widgets to find out what it was. Order is now overview → external ratings and links → where to watch → cast, then a "Your tracking" break followed by check-in, lists, rating, tags, seasons and watch history, with recommendations and drop-show at the tail as before.
- Settings opens as a list of sections rather than every form at once. All twelve accordions defaulted to expanded, so the chevrons had nothing to collapse on a first visit and the Integrations tab was seven full API-key forms stacked in one `max-w-2xl` column. Only the first section of each tab starts open now; the rest expand on demand, and the per-section `localStorage` memory that was already there keeps whatever each user opens. To keep a collapsed page navigable, the tabs gained a search box that filters sections by title and by what they hold ("backup", "pin", "ollama", "spoiler"), reaching across both tabs and showing each hit expanded. Two labels moved with it: the Preferences tab's first section, which repeated the name of the tab holding it, is now "Metadata & Region" — language, streaming region and spoiler protection — and "Integrations & Advanced" is "Integrations & Data", since "Advanced" named nothing in particular.
- Database migrations now run in their own short-lived `migrate` container, published as `ghcr.io/theshield2594/cataloggy-migrate` and tagged in lockstep with the other images, instead of at the start of the `api` container. `docker-compose.yml` gains a `migrate` service and the `api` service waits for it to finish, so a failed migration now shows up in `docker compose logs migrate` with `api` never having started, rather than as an `api` crash loop. Self-hosters running a copy of `docker-compose.yml` need to pick up both changes for the next update to apply its migrations.
- Each service image now ships only its own production dependencies. `pnpm prune --prod` runs against the whole workspace and keeps the union of every project's dependencies, so the API image carried the web app's React/Sentry/workbox tree and the addon image carried that plus the API's Prisma tree; both are now built with `pnpm deploy --filter`. Together with moving the Prisma CLI out of the running service, `node_modules` in the addon image drops from 456 MB to 64 MB and in the API image from 456 MB to 155 MB.
- pnpm no longer installs peer dependencies on its own (`autoInstallPeers: false`). Auto-installing makes a peer a real dependency of the package that named it, which is how `@prisma/client` — it names the `prisma` CLI so `prisma generate` is available — pulled the CLI and its Studio/dev tooling into production installs that only ever load the generated client. The peers this repo relies on are now declared by the projects that use them.
- Typography hierarchy: hero titles (media/game detail panels, the dashboard "Now Watching" and "Continue Watching" heroes) now use a heavier, tighter heading treatment (`font-extrabold`, tightened tracking) so a title separates cleanly from the metadata sitting directly beneath it, and the smallest supporting-metadata token (year, genre chips, episode counts) is held to a 12px legibility floor instead of 11px.
- Combined ("All") search now ranks movie and series results by how closely each title matches the query instead of strictly interleaving them one-for-one, so a strong match of either type no longer sits below a weaker one; equally-good matches still alternate as before.
- The "Add to list" menus (both the search quick-add popover and the media detail panel) now offer an inline "Create new list" path, so a profile with no lists yet can create one and add the item in a single step instead of hitting an empty dropdown.
- Type badges laid over posters now carry a dark text-halo and edge ring so their white labels stay legible on any theme accent (e.g. the lighter Letterboxd orange) and over bright poster art, rather than depending on a per-theme contrast check.
- The collapsible sidebar shows a one-time "hover to peek, or pin it open" tip the first time it expands, so the hover-to-expand/pin pattern is discoverable instead of hidden.
- `docker-compose.yml` services now use `restart: unless-stopped`, so the stack recovers automatically after a host reboot or crash instead of staying down.
- `apps/addon`'s Dockerfile is now a multi-stage build (matching `apps/api`/`apps/web`), shipping a smaller runtime image without the full pnpm workspace/devDependencies.
- The web app now detects an invalid or rotated API token globally (via a `WWW-Authenticate` response header on bearer-auth failures) and returns to the setup wizard, instead of every page showing a generic "Unable to connect" error for the rest of the session.
- The Stremio addon's mark-watched/scrobble endpoints now require a token derived from the shared API token, instead of relying solely on a spoofable `Origin` header check.
- TMDB and Trakt API calls now time out after 10s, matching the existing IGDB/Steam client behavior, instead of hanging indefinitely on a slow/unresponsive upstream.
- `GET /watch/stats/detailed` — the dashboard's stats panel, hit on every landing-page load — now aggregates in Postgres instead of in Node. It previously pulled the full 12-month event history *and* every distinct title the profile had ever watched into memory, then ran two more unbounded `IN (…)` queries over the combined ID list to build the genre histogram and top-rated list; six queries, all scaling linearly with total watch history. It is now two queries whose result sets are fixed-size (12 monthly buckets, 15 genres, 10 titles) no matter how large the history is. A new `idx_watchevent_series` index backs the distinct-series scan, which the existing indexes could not serve.
- Watchlist and custom-list Stremio catalogs no longer fetch and hydrate every item in the list before slicing to the requested limit. The sort key is the metadata title, which doesn't live on `ListItem`, so the slice genuinely has to happen after hydration — but the initial fetch is now capped rather than implicitly unbounded, so one catalog refresh on a pathological list can't fan out into thousands of metadata lookups and a TMDB backfill burst. Lists longer than the cap alphabetize their most recently added items.
- Profile resolution is cached for 30s (and cleared whenever a profile is created, updated or deleted), so the ~11 requests the dashboard fires on mount share one profile lookup instead of each paying its own. Because those requests go out in parallel and would all miss a cold cache, an in-flight lookup is shared with every caller waiting on the same profile rather than only with the ones that arrive after it resolves. The PIN gate is unaffected — it is re-evaluated per request against the cached profile.
- The API's rate limiter now gives the addon's service-to-service calls their own bucket and a larger budget, identified by a client header plus a valid API token. Keyed purely on IP, every Stremio client's traffic collapsed into one bucket, since the addon reaches the API from a single container IP and a Stremio home screen fans out to one request per enabled catalog. The limiter's in-memory, single-process assumption is now documented in place.
- The media detail panel, profile switcher and setup wizard are now loaded on demand rather than in the entry chunk, cutting the main bundle from 462 kB to 390 kB (135 kB → 121 kB gzip). None of the three renders on a normal dashboard load. (`lucide-react` was checked at the same time and does tree-shake correctly — only imported icons reach the bundle.)
- Every page now has an `h1`. Only Games and the 404 page had one; Dashboard, Search, Lists, Calendar, History, Stats and Settings all started at `h2`, so a screen-reader user got no page title in the heading outline. ### Security

- The Stremio routes' `?profileId=` selector names a profile, it no longer unlocks one. `resolveProfile` requires a verified profile-access token before serving a PIN-protected profile, but the Stremio routes pick their profile from a query parameter (or fall back to the default profile) without going through it — so holding the shared `API_TOKEN` was enough to read a locked profile's watchlist, history and continue-watching rows through `/watchlist`, `/continue`, `/recent` and the legacy `/stremio/catalog/*` paths, bypassing the boundary the header path enforces. All of them now apply the same check and answer 401 `profile_verification_required` when it fails, including when the selector is omitted and the resolved default profile is the locked one. The `/addon/stremio/:secret/…` URLs are deliberately unaffected: Stremio sends no headers and could never carry a PIN token, so the unguessable per-profile secret in the path remains the credential there.

- Custom lists are no longer served by UUID alone. `GET /stremio/list/:listId` looked its list up by id with no profile filter, so a caller acting as one profile could read another profile's list — including a PIN-protected one — by naming its UUID; it now resolves a profile the same way its sibling catalog routes do (`?profileId=`, defaulting to the oldest profile) and scopes the lookup to it, answering an out-of-scope list with the same 404 a nonexistent one gets. The addon's `list:` catalog branch additionally requires the list to be in that profile's enabled-catalog set, not merely owned by it: the manifest only ever advertises enabled lists, so a URL naming an unenabled one is a URL no client should have.
- The webhook secret no longer lands in the API's logs. Fastify runs with request logging on and its default serializer records the full URL, so `?token=<WEBHOOK_SECRET>` on the Plex/Jellyfin webhooks — the only form Plex can send, having no way to set custom headers — was written to the application log in plaintext and kept for as long as the log was. The request serializer now masks the values of `token` and similar parameters (`/webhooks/plex?token=REDACTED&profile=abc`), leaving the rest of the line intact. The header form is checked first when both are present, and authenticating via the query string logs a one-time warning per process pointing at `x-webhook-secret`, which Jellyfin's webhook plugin can set. A reverse proxy's own access log is outside Cataloggy's reach — the README now says so, and says what to do about it. Two smaller fixes in the same comparison: a repeated `?token=a&token=b` arrives as an array and was handed to `Buffer.from()`, which turns it into a buffer of zeroes rather than rejecting it, and the length pre-check counted characters where `timingSafeEqual` counts bytes, so a non-ASCII secret of matching character length raised a 500 instead of a 401.
- Profile PINs are stored under a salted KDF (scrypt, N=16384/r=8/p=1) instead of a bare SHA-256 digest. Unsalted SHA-256 is fast and precomputable, so a leaked database gave up short numeric PINs to an offline search almost immediately; scrypt makes each guess cost memory and milliseconds, and the per-PIN salt means guesses can't be shared across profiles. Existing PINs keep working — a hash in the old format still verifies and is rewritten in the new one the first time it's used, so nobody has to set their PIN again. Setting or changing a PIN now requires at least 4 characters (unlocking does not, so a shorter PIN chosen before this still opens its profile), and each successive lockout lasts twice as long as the last, up to an hour: the flat 5-minute lockout let anyone holding the shared `API_TOKEN` re-lock a profile every 5 minutes indefinitely for the price of five wrong guesses. A day without a failed attempt resets the escalation, and verifying the PIN clears it outright.
- The web app now purges the service worker's API response cache when the token changes, when it's cleared on sign-out or a rotated-token 401, and when a profile is left. Cached GET responses were already partitioned per identity, so no one could *read* another identity's entries — but the previous user's responses stayed in Cache Storage, readable by any same-origin script, for up to 24 hours. The purge deletes the cache from the page rather than only messaging the service worker, since no worker controls the page on a first load or a hard reload.
- The import endpoints (`POST /import`, `/import/csv`, `/import/external`) validate what they're handed instead of trusting the file. IMDb ids are checked against `tt<digits>` on every path — previously an arbitrary string could be persisted as an identifier, including one resolved from TMDB — numbers are range-checked whole numbers rather than merely `Number.isFinite` (so `1e20` no longer overflows a 32-bit `season`/`episode` column into an unhandled 500, and ratings stay on the 0-10 scale), and every array element is checked for being an object, so a payload like `{"version":1,"lists":[null]}` is skipped rather than dereferencing `null.name` into a 500. Each collection is also capped at 200,000 rows on top of the existing `MAX_BODY_SIZE_MB` byte ceiling — 10,000 for the Letterboxd formats, which carry no IMDb ids and so cost a TMDB search per title — and ratings and series progress are written in batches — an import used to issue one sequential round trip per rating and per progress row, so a few thousand rows meant a few thousand queries inside one request.
- `docker-compose.yml` takes the tag for all four app images from a single `CATALOGGY_IMAGE_TAG` setting (still defaulting to `latest`), so pinning a known-good `sha-<short-sha>`/`vX.Y.Z` build — and rolling back to it — is one line in `.env` rather than four edits to the compose file, with the images guaranteed to stay in lockstep. The Postgres image and the `node:26-alpine` base image the app images build on are now digest-pinned, so a rebuild uses the exact image that was tested rather than whatever the tag moved to; Dependabot proposes those bumps weekly, now including `docker-compose.yml`. Every service also gets `no-new-privileges`, and the Node services drop all Linux capabilities (`cap_drop: [ALL]`) — they run as non-root on high ports and need none. The database keeps its capabilities, which its entrypoint uses to prepare the data directory and drop privileges at init.
- The `fast-uri` overrides move to `^4.1.2` and `^3.1.5` (from `^4.1.1`/`^3.1.4`), both inside the range GHSA-7p8r-x3mc-p8w7 flags for host confusion via a backslash authority introducer. Both floors are needed: Fastify's serializer and schema compiler take the 4.x line, and `ajv` — reached through the same Fastify stack plus workbox — is still on 3.x.

- Profile PINs are now enforced server-side. Successful PIN verification (`POST /profiles/:id/verify`) issues a short-lived, HMAC-signed profile-access token that `resolveProfile` requires (via the `x-profile-token` header) for any PIN-protected profile. Previously the PIN was only a client-side prompt: anyone holding the shared `API_TOKEN` could read or mutate a "locked" profile's data — including a full `/export` — just by setting the `x-profile-id` header to that profile's UUID. The web app stores and sends the token automatically and re-prompts for the PIN when it expires.
- The AI-provider config endpoints (`POST /ai/config`, `POST /ai/test`) and the outbound AI request now reject URLs that target the cloud-metadata/link-local range (`169.254.0.0/16`, IPv6 link-local, `0.0.0.0`) or use a non-HTTP scheme, no longer follow redirects, and no longer reflect the upstream response body back to the caller — closing an SSRF-with-reflection vector reachable by an `API_TOKEN` holder. LAN/localhost LLM endpoints (Ollama, LM Studio, etc.) remain allowed.
- The SSRF guards on the AI-provider URL and the web-push endpoint now resolve the hostname and apply the same blocklist to every address the request could connect to, instead of only inspecting the literal host. A hostname is user input just like an IP: `metadata.google.internal`, a wildcard-DNS name such as `169-254-169-254.nip.io`, or any attacker-controlled A record passed the old check and reached the blocked address anyway. A name that fails to resolve is now rejected rather than allowed through. Both checks run immediately before the outbound request; saving an AI config still only validates syntax, so a brief resolver outage can't lock a self-hoster out of their own settings. This raises the bar on the static-DNS bypass but does not close DNS rebinding, which needs connection pinning — the existing `redirect: "error"` still blocks the cheaper redirect-based pivot.
- `DELETE /profiles/:id` now requires proof of the profile's PIN, the gate `PATCH /profiles/:id` already had. A PIN-protected profile could be deleted outright by anyone holding the shared `API_TOKEN` — and every child row cascades, so that took its watch history, lists, ratings, games and check-ins with it. The PIN kept a locked profile's data from being read or changed but not from being destroyed, which leaves exactly the household member it exists to stop unblocked. Deleting the profile you are in is still one confirm (the `x-profile-token` minted at PIN entry is the proof); deleting another profile's locked data asks for that PIN, under the same 5-attempt lockout `/verify` uses.
- `docker-compose.yml` now binds the Postgres port to `127.0.0.1` instead of `0.0.0.0`, so the database (which stores OAuth tokens) is no longer reachable from the LAN — or the internet, if the host is port-forwarded — bypassing `API_TOKEN`. The api/addon services still reach it over the internal Docker network.
- The API's built-in Stremio manifest and catalog routes (`/addon/stremio/...`) are no longer readable by anyone who can reach the server. They are exempt from `API_TOKEN` by construction — the add-on protocol sends no credentials — which left the default profile's watchlist, recently-watched and continue-watching lists (titles, posters, IMDb IDs) available unauthenticated, and `?profileId=` let a caller name *any* profile rather than only the default. The routes now live under an unguessable per-profile secret in the path (`/addon/stremio/<secret>/manifest.json`), derived from `API_TOKEN` via HMAC so it needs no configuration or storage and a leaked URL doesn't yield the token it came from. The secret is also the profile selector, so `?profileId=` no longer applies, and a custom-list catalog now resolves only within the profile the URL belongs to instead of by bare UUID. `GET /addon/config` returns the install URL for the requesting profile; the prefix-less paths stay registered but now sit behind the token check like every other route, so anyone who installed the API's own manifest URL (port `7000`) in a client has to reinstall it from the secret-scoped URL. Rotating `API_TOKEN` changes every add-on URL, and needs the same reinstall. The separate add-on service on port `7001` — the one Settings links to — is unchanged and still unauthenticated by protocol; the README's Security section now says so plainly.
- The Stremio "AI Picks" and "Recommended" catalogs are now built from the requesting profile's own history. Both seeded themselves from an unfiltered read — `getAiRecommendations` without a profile, and `watchEvent`/`seriesProgress` queries with no `profileId` — and cached the result under a key that named neither, so whoever asked first decided what everyone else was recommended. On a household with several profiles that recommended one person's titles to another (a PIN-protected profile included) and leaked what they had been watching.
- The Trakt OAuth flow now carries a `state` parameter. The callback has to be exempt from `API_TOKEN` (trakt.tv redirects a browser to it), and it previously accepted any authorization code it was handed, storing the resulting tokens under the fixed `"default"` id. Anyone who could lure the operator's browser to the callback URL with a code from *their* Trakt account bound the install to that account: the scheduled poller then imported a stranger's history and watchlist, and the operator's scrobbles flowed back out to them. `GET /trakt/oauth/authorize` (behind the token) now mints a single-use, 10-minute `state`, and the callback rejects anything that doesn't match before it looks at the code.
- The web app's `Content-Security-Policy` no longer allows connections to arbitrary hosts. `connect-src` was `'self' http: https: ws: wss:`, which permitted `fetch`/WebSocket to any origin and so removed the exfiltration protection the README credits the CSP with providing for the token kept in `localStorage`. It is now `'self'` plus the origins this deployment is configured to use (`VITE_API_BASE`, `VITE_ADDON_BASE`, and the `SENTRY_DSN` host when set), rendered into `dist/serve.json` from `apps/web/serve.template.json` at container start alongside the existing `config.js` write, since those values only exist then. Deployments where a browser reaches the API at some other address (e.g. an override set in Settings) can name it in the new `CSP_CONNECT_SRC_EXTRA` env var.
- `window.open` in the Trakt settings panel now passes `noopener`, which it — unlike `<a target="_blank">` — does not imply, so the trakt.tv tab no longer keeps a handle able to navigate the Cataloggy tab.
- Database dumps from `scripts/backup.sh` are no longer left committable or world-readable. A dump is a full copy of the database — every profile's data plus the stored Trakt/Twitch/Steam OAuth tokens — but `backups/` was ignored only by `.dockerignore`, so running the script from the repo root and then `git add -A` would commit one into git history, and the file was written at the default umask (typically `0644`) into a directory whose permissions were never set. `backups/` and `*.sql.gz` are now git-ignored (`*.sql` deliberately isn't — Prisma migrations are tracked `.sql` files), and `backup.sh` runs under `umask 077`, `chmod`s `$BACKUP_DIR` to `700` and each dump to `600`. Dumps written before this change keep their old permissions; `chmod 700 backups && chmod 600 backups/*.sql.gz` fixes them, and a dump already committed needs the git history rewritten and the exposed OAuth tokens revoked.

The "More" tab highlights while one of its destinations is open, and the sheet closes on Escape, on a backdrop tap, or on choosing a destination, returning focus to the tab that opened it.
- `/search` no longer throws an uncaught exception (and a bare 500) when the upstream TMDB request fails.
- Bumped a transitive `serialize-javascript` dependency (via `workbox-build`) to patch a high-severity RCE advisory ([GHSA-5c6j-r48x-rmvq](https://github.com/advisories/GHSA-5c6j-r48x-rmvq)).
- `getDefaultWatchlist` now retries on a concurrent-create race instead of throwing a raw Prisma error (matching `getDefaultCollection`'s existing behavior).
- `PATCH /profiles/:id` now requires the profile's current PIN to change or remove an *existing* PIN (reusing the same verification/lockout logic as `/verify`); previously anyone with Settings access could strip another profile's PIN protection without ever knowing it.
- The addon's mutation-token check no longer assumes the incoming token is a string — a repeated query param (`?token=a&token=b`) would have thrown instead of being rejected cleanly.
- `dockerpublish.yml` reads the git ref type/name from the runner's `GITHUB_REF_TYPE`/`GITHUB_REF_NAME` environment variables instead of interpolating `github.ref_type`/`github.ref_name` into a shell script.
