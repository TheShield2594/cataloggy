# Changelog

All notable changes to Cataloggy are documented in this file, starting from this entry onward. Earlier history predates this file — see `git log` for the full commit history.

Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Dates are UTC.

## [Unreleased]

### Added

- iOS launch screens for the installed PWA (`apple-touch-startup-image`), covering iPhone SE through iPhone 17 Pro Max and the current iPads in both orientations, so launching from the home screen shows the branded splash instead of a blank white flash. Generated by `scripts/generate-splash.mjs`; excluded from the service-worker precache so they cost nothing at install time.
- Docker images are now also published with a `sha-<short-sha>` tag (and a semver tag for `vX.Y.Z` tag pushes), so self-hosters can pin a known-good version and roll back instead of only ever running `:latest`.
- pnpm is now pinned to 11 (from 9.12.0). pnpm 11 stopped reading settings from `package.json` and `.npmrc`, so the dependency `overrides` (several of them CVE pins) and the hoisted node-linker moved to `pnpm-workspace.yaml`, joined by an `allowBuilds` list — pnpm no longer runs a dependency's install scripts unless it's approved, and Prisma and esbuild both need theirs. No resolved dependency version changed: `pnpm-lock.yaml` is untouched by the migration.
- CI, the Docker publish pipeline and the weekly security scan now run on Node 26, matching the `node:26-alpine` base image every app ships on, instead of the end-of-life Node 20 they were pinned to.
- CI now applies every Prisma migration against a real Postgres service before running tests, catching broken migrations before they reach a self-hoster's `api` container.
- CI now runs CodeQL static analysis and a `pnpm audit` dependency check (weekly, plus every push/PR).
- README: guidance on pinning/rolling back image versions, and on recovering if a database migration fails on container start.
- `CONTRIBUTING.md`.
- A "Sync Status" Settings section and `GET /settings/job-status` endpoint surfacing the last failure of each scheduled background job (Trakt poll/watchlist sync, episode notifications, AI recs refresh, Steam sync, scrobble cleanup), so a self-hoster without Sentry configured can still notice a silently-broken sync.
- A visible "update available" prompt for the web PWA instead of the service worker silently swapping itself in.
- `PATCH /profiles/:id` for renaming a profile or setting/changing/removing its PIN, plus a Settings UI to do so — previously only creating and switching profiles was possible from the app; deleting one (already supported server-side) had no UI entry point at all.
- `apps/web` now has a test suite (Vitest + Testing Library + jsdom, run by `pnpm test` like the other workspaces) — previously the ~11k-line frontend was covered only by ESLint and the type checker, with nothing exercising its behavior. Covers the pure logic (`timeAgo`/`timeUntil`, carousel edge fade and scroll state, runtime/status formatting, Continue Watching progress), the `useSearchFilters` URL-param reducer, the `api.ts` request wrapper (auth headers, both 401 paths, error decoding), and the profile switcher / PIN entry flow.
- Test coverage for previously-untested modules: `lib/collection.ts`, `lib/watchlist.ts`, `lib/series-progress.ts`, `routes/watch.ts`, the Plex/Jellyfin webhook handlers, and the new profile-management/job-status endpoints. `apps/addon` now has a test suite of its own (previously it had none), covering profile scoping and mark-watched feedback.

### Changed

- Settings opens as a list of sections rather than every form at once. All twelve accordions defaulted to expanded, so the chevrons had nothing to collapse on a first visit and the Integrations tab was seven full API-key forms stacked in one `max-w-2xl` column. Only the first section of each tab starts open now; the rest expand on demand, and the per-section `localStorage` memory that was already there keeps whatever each user opens. To keep a collapsed page navigable, the tabs gained a search box that filters sections by title and by what they hold ("backup", "pin", "ollama", "spoiler"), reaching across both tabs and showing each hit expanded. Two labels moved with it: the Preferences tab's first section, which repeated the name of the tab holding it, is now "Metadata & Region" — language, streaming region and spoiler protection — and "Integrations & Advanced" is "Integrations & Data", since "Advanced" named nothing in particular.
- Database migrations now run in their own short-lived `migrate` container, published as `ghcr.io/theshield2594/cataloggy-migrate` and tagged in lockstep with the other images, instead of at the start of the `api` container. `docker-compose.yml` gains a `migrate` service and the `api` service waits for it to finish, so a failed migration now shows up in `docker compose logs migrate` with `api` never having started, rather than as an `api` crash loop. Self-hosters running a copy of `docker-compose.yml` need to pick up both changes for the next update to apply its migrations.
- Each service image now ships only its own production dependencies. `pnpm prune --prod` runs against the whole workspace and keeps the union of every project's dependencies, so the API image carried the web app's React/Sentry/workbox tree and the addon image carried that plus the API's Prisma tree; both are now built with `pnpm deploy --filter`. Together with moving the Prisma CLI out of the running service, `node_modules` in the addon image drops from 456 MB to 64 MB and in the API image from 456 MB to 155 MB.
- pnpm no longer installs peer dependencies on its own (`autoInstallPeers: false`). Auto-installing makes a peer a real dependency of the package that named it, which is how `@prisma/client` — it names the `prisma` CLI so `prisma generate` is available — pulled the CLI and its Studio/dev tooling into production installs that only ever load the generated client. The peers this repo relies on are now declared by the projects that use them.
- Typography hierarchy: hero titles (media/game detail panels, the dashboard "Now Watching" and "Continue Watching" heroes) now use a heavier, tighter heading treatment (`font-extrabold`, tightened tracking) so a title separates cleanly from the metadata sitting directly beneath it, and the smallest supporting-metadata token (year, genre chips, episode counts) is held to a 12px legibility floor instead of 11px.
- Combined ("All") search now ranks movie and series results by how closely each title matches the query instead of strictly interleaving them one-for-one, so a strong match of either type no longer sits below a weaker one; equally-good matches still alternate as before.
- The "Add to list" menus (both the search quick-add popover and the media detail panel) now offer an inline "Create new list" path, so a profile with no lists yet can create one and add the item in a single step instead of hitting an empty dropdown.
- Type badges laid over posters now carry a dark text-halo and edge ring so their white labels stay legible on any theme accent (e.g. the lighter Letterboxd orange) and over bright poster art, rather than depending on a per-theme contrast check.
- The collapsible sidebar shows a one-time "hover to peek, or pin it open" tip the first time it expands, so the hover-to-expand/pin pattern is discoverable instead of hidden.
- `docker-compose.yml` services now use `restart: unless-stopped`, so the stack recovers automatically after a host reboot or crash instead of staying down.
- `apps/addon`'s Dockerfile is now a multi-stage build (matching `apps/api`/`apps/web`), shipping a smaller runtime image without the full pnpm workspace/devDependencies.
- The web app now detects an invalid or rotated API token globally (via a `WWW-Authenticate` response header on bearer-auth failures) and returns to the setup wizard, instead of every page showing a generic "Unable to connect" error for the rest of the session.
- The Stremio addon's mark-watched/scrobble endpoints now require a token derived from the shared API token, instead of relying solely on a spoofable `Origin` header check.
- TMDB and Trakt API calls now time out after 10s, matching the existing IGDB/Steam client behavior, instead of hanging indefinitely on a slow/unresponsive upstream.
- `GET /watch/stats/detailed` — the dashboard's stats panel, hit on every landing-page load — now aggregates in Postgres instead of in Node. It previously pulled the full 12-month event history *and* every distinct title the profile had ever watched into memory, then ran two more unbounded `IN (…)` queries over the combined ID list to build the genre histogram and top-rated list; six queries, all scaling linearly with total watch history. It is now two queries whose result sets are fixed-size (12 monthly buckets, 15 genres, 10 titles) no matter how large the history is. A new `idx_watchevent_series` index backs the distinct-series scan, which the existing indexes could not serve.
- Watchlist and custom-list Stremio catalogs no longer fetch and hydrate every item in the list before slicing to the requested limit. The sort key is the metadata title, which doesn't live on `ListItem`, so the slice genuinely has to happen after hydration — but the initial fetch is now capped rather than implicitly unbounded, so one catalog refresh on a pathological list can't fan out into thousands of metadata lookups and a TMDB backfill burst. Lists longer than the cap alphabetize their most recently added items.
- Profile resolution is cached for 30s (and cleared whenever a profile is created, updated or deleted), so the ~11 requests the dashboard fires on mount share one profile lookup instead of each paying its own. Because those requests go out in parallel and would all miss a cold cache, an in-flight lookup is shared with every caller waiting on the same profile rather than only with the ones that arrive after it resolves. The PIN gate is unaffected — it is re-evaluated per request against the cached profile.
- The API's rate limiter now gives the addon's service-to-service calls their own bucket and a larger budget, identified by a client header plus a valid API token. Keyed purely on IP, every Stremio client's traffic collapsed into one bucket, since the addon reaches the API from a single container IP and a Stremio home screen fans out to one request per enabled catalog. The limiter's in-memory, single-process assumption is now documented in place.
- The media detail panel, profile switcher and setup wizard are now loaded on demand rather than in the entry chunk, cutting the main bundle from 462 kB to 390 kB (135 kB → 121 kB gzip). None of the three renders on a normal dashboard load. (`lucide-react` was checked at the same time and does tree-shake correctly — only imported icons reach the bundle.)
- Every page now has an `h1`. Only Games and the 404 page had one; Dashboard, Search, Lists, Calendar, History, Stats and Settings all started at `h2`, so a screen-reader user got no page title in the heading outline. Pages with a visible title use it as the `h1` (with their section headings shifted down a level to keep the outline gapless); Dashboard, Search and Lists have no visible title by design and carry a visually hidden one instead. The profile switcher, which is a full page on first run and a modal afterwards, titles itself `h1` or `h2` to match.
- Form fields that were labelled only by a `placeholder` — which disappears on input and isn't reliably announced — now carry a real accessible name: the main search box, both list-name fields, the list rename box, every PIN and profile-name field in the switcher and in Settings, the API-token/OMDB/RPDB key fields, the game notes box, the tag box, the watch-date picker, the raw-JSON AI config, and the import-format and year-in-review selects.

### Security

- Profile PINs are now enforced server-side. Successful PIN verification (`POST /profiles/:id/verify`) issues a short-lived, HMAC-signed profile-access token that `resolveProfile` requires (via the `x-profile-token` header) for any PIN-protected profile. Previously the PIN was only a client-side prompt: anyone holding the shared `API_TOKEN` could read or mutate a "locked" profile's data — including a full `/export` — just by setting the `x-profile-id` header to that profile's UUID. The web app stores and sends the token automatically and re-prompts for the PIN when it expires.
- The AI-provider config endpoints (`POST /ai/config`, `POST /ai/test`) and the outbound AI request now reject URLs that target the cloud-metadata/link-local range (`169.254.0.0/16`, IPv6 link-local, `0.0.0.0`) or use a non-HTTP scheme, no longer follow redirects, and no longer reflect the upstream response body back to the caller — closing an SSRF-with-reflection vector reachable by an `API_TOKEN` holder. LAN/localhost LLM endpoints (Ollama, LM Studio, etc.) remain allowed.
- The SSRF guards on the AI-provider URL and the web-push endpoint now resolve the hostname and apply the same blocklist to every address the request could connect to, instead of only inspecting the literal host. A hostname is user input just like an IP: `metadata.google.internal`, a wildcard-DNS name such as `169-254-169-254.nip.io`, or any attacker-controlled A record passed the old check and reached the blocked address anyway. A name that fails to resolve is now rejected rather than allowed through. Both checks run immediately before the outbound request; saving an AI config still only validates syntax, so a brief resolver outage can't lock a self-hoster out of their own settings. This raises the bar on the static-DNS bypass but does not close DNS rebinding, which needs connection pinning — the existing `redirect: "error"` still blocks the cheaper redirect-based pivot.
- `DELETE /profiles/:id` now requires proof of the profile's PIN, the gate `PATCH /profiles/:id` already had. A PIN-protected profile could be deleted outright by anyone holding the shared `API_TOKEN` — and every child row cascades, so that took its watch history, lists, ratings, games and check-ins with it. The PIN kept a locked profile's data from being read or changed but not from being destroyed, which leaves exactly the household member it exists to stop unblocked. Deleting the profile you are in is still one confirm (the `x-profile-token` minted at PIN entry is the proof); deleting another profile's locked data asks for that PIN, under the same 5-attempt lockout `/verify` uses.
- `docker-compose.yml` now binds the Postgres port to `127.0.0.1` instead of `0.0.0.0`, so the database (which stores OAuth tokens) is no longer reachable from the LAN — or the internet, if the host is port-forwarded — bypassing `API_TOKEN`. The api/addon services still reach it over the internal Docker network.
- The API's built-in Stremio manifest and catalog routes (`/addon/stremio/...`) are no longer readable by anyone who can reach the server. They are exempt from `API_TOKEN` by construction — the add-on protocol sends no credentials — which left the default profile's watchlist, recently-watched and continue-watching lists (titles, posters, IMDb IDs) available unauthenticated, and `?profileId=` let a caller name *any* profile rather than only the default. The routes now live under an unguessable per-profile secret in the path (`/addon/stremio/<secret>/manifest.json`), derived from `API_TOKEN` via HMAC so it needs no configuration or storage and a leaked URL doesn't yield the token it came from. The secret is also the profile selector, so `?profileId=` no longer applies, and a custom-list catalog now resolves only within the profile the URL belongs to instead of by bare UUID. `GET /addon/config` returns the install URL for the requesting profile; the prefix-less paths stay registered but now sit behind the token check like every other route, so anyone who installed the API's own manifest URL (port `7000`) in a client has to reinstall it from the secret-scoped URL. Rotating `API_TOKEN` changes every add-on URL, and needs the same reinstall. The separate add-on service on port `7001` — the one Settings links to — is unchanged and still unauthenticated by protocol; the README's Security section now says so plainly.
- The Stremio "AI Picks" and "Recommended" catalogs are now built from the requesting profile's own history. Both seeded themselves from an unfiltered read — `getAiRecommendations` without a profile, and `watchEvent`/`seriesProgress` queries with no `profileId` — and cached the result under a key that named neither, so whoever asked first decided what everyone else was recommended. On a household with several profiles that recommended one person's titles to another (a PIN-protected profile included) and leaked what they had been watching.
- The Trakt OAuth flow now carries a `state` parameter. The callback has to be exempt from `API_TOKEN` (trakt.tv redirects a browser to it), and it previously accepted any authorization code it was handed, storing the resulting tokens under the fixed `"default"` id. Anyone who could lure the operator's browser to the callback URL with a code from *their* Trakt account bound the install to that account: the scheduled poller then imported a stranger's history and watchlist, and the operator's scrobbles flowed back out to them. `GET /trakt/oauth/authorize` (behind the token) now mints a single-use, 10-minute `state`, and the callback rejects anything that doesn't match before it looks at the code.
- The web app's `Content-Security-Policy` no longer allows connections to arbitrary hosts. `connect-src` was `'self' http: https: ws: wss:`, which permitted `fetch`/WebSocket to any origin and so removed the exfiltration protection the README credits the CSP with providing for the token kept in `localStorage`. It is now `'self'` plus the origins this deployment is configured to use (`VITE_API_BASE`, `VITE_ADDON_BASE`, and the `SENTRY_DSN` host when set), rendered into `dist/serve.json` from `apps/web/serve.template.json` at container start alongside the existing `config.js` write, since those values only exist then. Deployments where a browser reaches the API at some other address (e.g. an override set in Settings) can name it in the new `CSP_CONNECT_SRC_EXTRA` env var.
- `window.open` in the Trakt settings panel now passes `noopener`, which it — unlike `<a target="_blank">` — does not imply, so the trakt.tv tab no longer keeps a handle able to navigate the Cataloggy tab.
- Database dumps from `scripts/backup.sh` are no longer left committable or world-readable. A dump is a full copy of the database — every profile's data plus the stored Trakt/Twitch/Steam OAuth tokens — but `backups/` was ignored only by `.dockerignore`, so running the script from the repo root and then `git add -A` would commit one into git history, and the file was written at the default umask (typically `0644`) into a directory whose permissions were never set. `backups/` and `*.sql.gz` are now git-ignored (`*.sql` deliberately isn't — Prisma migrations are tracked `.sql` files), and `backup.sh` runs under `umask 077`, `chmod`s `$BACKUP_DIR` to `700` and each dump to `600`. Dumps written before this change keep their old permissions; `chmod 700 backups && chmod 600 backups/*.sql.gz` fixes them, and a dump already committed needs the git history rewritten and the exposed OAuth tokens revoked.

### Fixed

- Focus rings no longer render a white halo on the dark themes. `focus-visible:ring-offset-2` was used at 21 places without `--tw-ring-offset-color` ever being set, leaving it at Tailwind's `#fff` default, so the 2px "offset" painted a solid white band around every focused control on Dark, Glass, Midnight Cinema and Letterboxd — a white box, not a focus indicator. Tailwind registers that property with `inherits: false`, so it cannot be themed once on `:root` alongside `--bg-0`; the declaration has to land on the focused element itself. A `.focus-ring-offset` class now carries the width and a `var(--bg-0)` colour together, so the two cannot drift apart, and replaces the bare offset utility everywhere it was used.
- The history type filter now filters the whole history rather than the page already loaded. `HistoryPage` filtered `events` in memory while the API paginates 25 rows at a time, so on a history whose 25 most recent events were all episodes, selecting "Movies" showed the empty state — and that state claimed there was no watch history at all. `GET /watch/history` takes a `type` query parameter (unrecognised values ignored, not rejected), the filter resets pagination, and the empty copy now distinguishes "no movies" from "no history".
- The dashboard reports a failed section instead of dropping it. Detailed stats, AI recommendations, AI config and the calendar reported failure only to the console, and the render guards then removed the section outright: the Upcoming column vanished and the two-column grid silently reflowed to one, and the Discover section disappeared entirely. Each now keeps its container and shows an error with a Retry, and the header says "Streak unavailable" rather than presenting a 0-day streak as the real number. Trending's failure state gained the same Retry.
- List rename no longer commits on blur. Anything that moved focus — clicking elsewhere, tabbing, switching windows — saved whatever was in the field, with no Escape handler and no way back to the original name once you had typed over it, and clicking the ✓ button blurred the input first so the rename fired twice. Blur and Escape now discard; Enter and ✓ commit.
- The Lists error banner clears on success. Five handlers set it and none reset it, so one transient failure pinned the banner for the rest of the session even after the retry worked.
- The search quick-add dropdown no longer announces itself as an ARIA menu it never implemented. It declared `role="menu"` with `menuitem` children and `aria-haspopup="menu"` while providing none of the arrow-key navigation, Escape, or focus management that contract promises — telling assistive-tech users to expect behaviour that was not there. The panel holds a text field for the inline create flow, which the menu pattern does not allow, so it is now a labelled disclosure: the trigger keeps `aria-expanded`/`aria-controls`, focus moves into the panel on open, Escape closes and restores focus to the trigger, and moving focus out closes it. The trigger can also dismiss its own panel again — the outside-click listener closed it on mousedown and the click that followed reopened it.
- The command palette scrolls the keyboard-selected row into view. Arrowing past the fold of its `max-h-[60vh]` list moved the highlight somewhere the user could not see, with no indication anything was selected. Escape also no longer closes two layers at once: the palette registered a window-level handler that bypassed the `useEscapeKey` stack, so opening a title's detail panel and pressing Escape closed the panel *and* the palette. Closing the panel now drops back to the palette with its query and results intact.
- The profile switcher locks background scroll and joins the Escape stack, like every other modal in the app. It called `useFocusTrap` but not `useScrollLock`, so the page behind scrolled freely — on iOS Safari, under the overlay — and its own window `keydown` listener sat outside the ordering `useEscapeKey` exists to enforce. Both are gated so the full-page first-run variant is unaffected.
- The update prompt no longer covers the mobile tab bar or overflows a narrow screen. It pinned itself 24px from the bottom edge at `z-[110]`, landing on top of the bottom nav and ignoring the safe-area inset the nav accounts for, and its single-line row of copy plus Reload plus dismiss was wider than a 320–390px viewport with no `max-width` and no wrapping. It now clears the nav the way toasts already did, and wraps within the viewport.
- A first visit on a dark-mode device no longer flashes cream before the theme applies. `theme-init.js`, which runs inline before paint, fell back to `"light"` when nothing was stored, while `useTheme` falls back to `prefers-color-scheme` — so the initial loader and first paint rendered on `#faf6ef` and then jumped to dark once React mounted. The inline script now uses the same fallback the hook does.
- A Settings section that starts collapsed no longer flashes its whole body open and slides shut as the page loads. The height animation ran on the first render as well as on every toggle, measuring the panel and animating from that height down to zero. "Sync Status" was the only section it could affect before; with most of the page now collapsed by default it would have been the first thing a visit showed.
- The Plex and Jellyfin webhooks now resolve a profile before writing. They were the only data-writing routes that never registered `resolveProfile`, so every scrobble reached `recordWatchEvent` with `profileId: undefined` — which Prisma reads as "no filter", letting the same-day dedupe match another profile's event and increment *its* play count, and rejects on create, so a first-of-the-day scrobble came back as a bare 500. A scrobble now lands in the profile named by `?profile=<id>` on the webhook URL, else the profile whose name matches the Plex/Jellyfin account, else the default profile. `recordWatchEvent` takes an explicit `profileId` argument now, so the type checker catches a caller that has none rather than leaving it to a non-null assertion.
- "Sync Steam" and "Import from Trakt" now write to the profile that pressed the button. Both resolved `getDefaultProfileId()` instead of reading `x-profile-id` — which the web client sends on every request — so on a multi-profile install they silently populated the oldest profile's games, watch events, series progress and watchlist. The scheduled variants of the same jobs still use the default profile, since they have no request to resolve.
- Export/import can round-trip a real library again. `/export` is unbounded but `/import` inherited Fastify's stock 1 MiB body limit, so somewhere north of ~5k watch events the backup the app had just produced could no longer be restored into it, and the failure was a bare 413. The limit is now 32 MB (`MAX_BODY_SIZE_MB`, ~200k watch events) and exceeding it returns a message that names the limit and the variable that raises it.
- White-on-accent text now clears WCAG AA in every theme. `bg-claw-500 text-white` sat at 2.42–3.65:1 in four of the five themes, and accent-coloured text was worse — the "Unable to connect to the API" headline rendered at 1.53:1 in the light theme. Two contrast-checked tokens replace the fixed white: `--on-accent` for text on an accent fill (including the `hover:bg-claw-600` state, whose fill moved in the light and glass themes to keep the pair above the threshold) and `--accent-text` for accent-coloured text on a page background. `--text-mute` was darkened in the light, midnight and letterboxd themes. Every pairing measures at ≥4.5:1 on painted pixels across all five themes.
- The API and addon images build again. pnpm 11 asks before removing a modules directory and aborts outright when there is no TTY to ask on, so `pnpm prune --prod` failed every build with `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`. That step is gone in favour of `pnpm deploy`, which does not purge anything.
- The Stremio addon now identifies which profile it is acting for, instead of silently depending on the API's single-profile fallback. Creating a second profile used to break every call the addon made — catalogs, personal recommendations, series progress, and both `/watch` and `/scrobble` writes all started failing with `x-profile-id header is required`, and "Mark Watched" still reported success. A profile is bound to an addon *installation* through its URL (`/p/<profile-id>/manifest.json`, the base Stremio derives every other request from); the Settings page shows the URL for the profile you're using. URLs without the prefix keep working and resolve to the oldest profile.
- The Stremio addon's catalog selection is now per profile. It lived in one KV row with no profile dimension and its list picker queried custom lists unfiltered, so enabling a catalog enabled it for every profile on the install, two profiles could not expose different catalogs to Stremio, and the Settings picker listed every profile's custom lists — including a PIN-protected profile's. Both `/addon/config` endpoints now resolve a profile and scope their list queries to it, the manifest reads the config of the profile it is built for, and the addon service keys its enabled-catalog cache per profile instead of letting whichever profile asked first decide for everyone for the next 60s. A migration copies an existing install's selection onto the default profile, so nothing has to be re-picked. Distinct from #336, which is about the read path for list *contents*.
- The addon's "Mark Watched" subtitle no longer claims success when nothing was recorded: a failed write, a rejected mutation token, and an unrecognised profile each say so in the text Stremio displays.
- Carousel edge fades no longer erase a focused card's ring. The fade was a `mask-image` on the scroll container, and a mask removes the pixels it covers — so a card resting against a scrollable edge showed no `focus-visible` ring at all, at precisely the spot where the row is hardest to read. It is now two overlaid gradients, which dim those pixels without deleting them, plus `scroll-padding` matching the fade width so a card the browser scrolls into view stops clear of the fade. The track also gained 8px of room inside its own clip box (`p-2` against a `-m-2` wrapper, same position on the page), since `overflow-x: auto` clips vertically too and was cutting the hover lift, the `card-lift` shadow and the ring offset. Applies to every dashboard row and the detail panel's cast and recommendations rows.
- The mobile tab bar no longer overflows the viewport. Eight tabs whose labels could not shrink measured 344px against a 320px screen, and `overflow-x: hidden` on the body clipped rather than scrolled the excess, costing Settings its label and half its hit area; even at 430px the bar had exactly zero slack. It is now the conventional five — Dashboard, Search, Lists, Calendar and a "More" sheet holding Games, History, Stats and Settings — measured at 320px on the nose with every label legible, each tab 64×58px against the 44px touch-target floor. The "More" tab highlights while one of its destinations is open, and the sheet closes on Escape, on a backdrop tap, or on choosing a destination, returning focus to the tab that opened it.
- `/search` no longer throws an uncaught exception (and a bare 500) when the upstream TMDB request fails.
- Bumped a transitive `serialize-javascript` dependency (via `workbox-build`) to patch a high-severity RCE advisory ([GHSA-5c6j-r48x-rmvq](https://github.com/advisories/GHSA-5c6j-r48x-rmvq)).
- `getDefaultWatchlist` now retries on a concurrent-create race instead of throwing a raw Prisma error (matching `getDefaultCollection`'s existing behavior).
- `PATCH /profiles/:id` now requires the profile's current PIN to change or remove an *existing* PIN (reusing the same verification/lockout logic as `/verify`); previously anyone with Settings access could strip another profile's PIN protection without ever knowing it.
- The addon's mutation-token check no longer assumes the incoming token is a string — a repeated query param (`?token=a&token=b`) would have thrown instead of being rejected cleanly.
- `dockerpublish.yml` reads the git ref type/name from the runner's `GITHUB_REF_TYPE`/`GITHUB_REF_NAME` environment variables instead of interpolating `github.ref_type`/`github.ref_name` into a shell script.
